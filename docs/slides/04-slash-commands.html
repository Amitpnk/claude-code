What are slash commands?

Shortcuts you type inside a Claude Code session, starting with /, that trigger a predefined action or workflow instantly — without writing out a full prompt.
✓
Instant & unambiguous
No prompt to parse — the command runs the action directly.
✓
Autocomplete
Type / and tab through every available command.
✓
Built-in vs custom
Today is the built-in set. Writing your own comes in Video 12.
terminal
~/project $ claude
> /
  /clear        /compact
  /model        /resume
  /rename       /export
  /usage        /stats
  /config       /permissions

The daily drivers

Five commands you'll reach for in almost every session.
CommandWhat it doesWhen to use it
/clearWipes the conversation contextStarting a new, unrelated task
/compactSummarizes & trims historyContext window is filling up
/modelSwitches model for this sessionNeed more or less power temporarily
/resumeReopens a previous sessionContinuing yesterday's work
/helpLists every available commandYou forgot a command name

What is a session?

One conversation with Claude Code — everything from claude to /exit.
✓
It has a unique ID
Plus the full message history, every file read, every tool result, and the working directory.
✓
Saved automatically
Written to ~/.claude/projects/ — nothing to remember to do.
✓
Resumable any time
Even after you close the terminal. Pick up exactly where you left off.
resuming work
~/project $ claude -r
  # pick a past session to continue

> /resume
  # jump to another session
  # mid-session, then come back

Session discipline

Five habits that keep a session sharp instead of sprawling.
01
One session = one task
Mixed goals mean mixed context — and worse answers.
02
Name it immediately
A named session is one you can actually find later.
03
Commit frequently within it
Small checkpoints make it safe to keep going.
04
Use /btw for quick questions
Ask a side question without derailing the main thread.
05
Export before a big refactor
A written record of the reasoning, not just the diff.

Choosing a model with /model

Four models, four jobs. Switching takes one command.
01
Fable 5
A highly capable brain that answers questions, writes, codes, and analyses documents — the top tier, for the most demanding reasoning and long-horizon work.
02
Opus 5
Built for intense, multi-step projects, advanced writing, and coding. Slower and pricier than Sonnet, but it handles complex challenges best.
03
Sonnet 5
The middle ground — the most popular, fast, balanced model for everyday coding, writing, and research.
04
Haiku 4.5
The fastest and cheapest. Use it for simple, repetitive, or exploratory tasks where you don't need deep reasoning.

The power-user pattern

Match the model to the phase, not to the project.
Plan on Opus
architecture & specs
→
/model
switch mid-session
→
Build on Sonnet
reliable code generation

Use the stronger model where the thinking happens — architecture, specs, hard decisions. Once those are made, switch down for implementation: the thinking is done, and you just need dependable output.

Common mistakes

 

Do this

  • One session per task, named on day one
  • Check /usage on long sessions
  • Match the model to the phase of the work
  • Run /help when a command name slips your mind

Not this

  • One endless session across weeks of unrelated work
  • Staying on the biggest model for every keystroke
  • Ignoring permission prompts instead of setting /permissions
  • Guessing at command names instead of autocompleting

Built-in today. Custom next.

 

These built-in commands cover the mechanics of running a session well. But the real leverage comes when you encode your own repeated workflows as commands — that's the entire subject of Video 12.

Key takeaways

 
✓

Slash commands are direct instructions, not prose — faster and unambiguous.

✓

A session is one conversation, saved automatically and resumable. Keep it to one task, and name it.

✓

/model is a phase decision: plan on the stronger model, implement on the faster one.

✓

/usage, /stats, /status, and /permissions keep you informed instead of surprised.

✓

Build the habit loop: named starts, compact near limits, usage checks before you wrap up.
