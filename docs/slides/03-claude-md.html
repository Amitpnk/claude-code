Why CLAUDE.md?

LLMs don't have memory.
✗

Claude Code can't remember anything from a previous session.

✗

So you end up repeating the same instructions across sessions.

✗

Repeating instructions is cumbersome and error-prone — easy to miss something in the prompt.

✗

That missed detail leads to inconsistent code generation, session to session.

What is CLAUDE.md?

A persistent system prompt for your project.
✓
Special project-level instruction file
Used by Claude Code to guide how it behaves while working on your codebase.
✓
Say it once, not every session
Project structure, coding conventions, how to run/build/test, what tools to use.
✓
Loaded automatically
Claude uses it as context every time — no re-prompting required.

Creating CLAUDE.md

Two ways to get one.
01
Manually
Create the CLAUDE.md file yourself and write the sections you already know matter.
02
Using /init
Let Claude scan the repo and generate a first draft for you.

Why /init helps

Situation → why /init is the faster path.
Onboarding a codebase you didn't write
→
Faster than reading everything yourself.
Large repos with many files
→
Claude can spot patterns you might forget to document.
You're new to CLAUDE.md
→
A good way to see what the format looks like.
Quick prototypes
→
You don't want to invest time writing docs.

How /init works

 
01
Triggers an internal agent
It takes over the scanning and writing task.
02
Scans high-signal files first
package.json, requirements.txt, config files, README.md.
03
Reads the directory tree
Builds a picture of the overall structure.
04
Infers stack, layout, naming
Tech stack, folder layout, and naming conventions.
05
Writes CLAUDE.md to project root
With whatever context it inferred.

The generated file is a draft

 

~30% useful out of the box

  • Tech stack
  • Folder layout
  • Naming conventions it could infer

~70% you still have to write

  • Workflows and constraints
  • What to avoid
  • Deployment targets

Content of CLAUDE.md

Six sections, each answering one question.

Project Context

A short description of the project so Claude immediately understands what it's building or modifying.
This is a todo application
for demo that stores
projects and their tasks.

Architecture

Explains how the codebase is structured and where things belong.
- routes live in routers/
- business logic lives in
  services/
- schemas live in schemas/
- persistence logic lives
  in repository/

Code Style

Tells Claude how code should look and what conventions to follow.
- Use Python type hints
  everywhere
- Prefer Pydantic models for
  request/response schemas
- Keep functions small
  and focused

Preferred Libraries

What tools and frameworks should be used.
- Use FastAPI for the API
- Use Pydantic for validation
- Use SQLAlchemy for the ORM
- Do not introduce new deps
  unless necessary

Commands

Exact commands for running, testing, and maintaining the project.
- Install: npm install
- Dev server: npm run dev
- Tests: npm test

Critical Rules

Highlights critical warnings, edge cases, and things to avoid.
- Do not modify database.py
  unless absolutely necessary
- Employee IDs are provided
  by the client — never
  auto-generate UUIDs

Key takeaways

 
✓

Claude Code has no memory across sessions — CLAUDE.md is how you stop repeating yourself.

✓

It's a persistent system prompt: structure, conventions, commands, tools — written once, loaded every time.

✓

/init gives you a fast first draft, but only gets you ~30% of the way there.

✓

The other 70% — workflows, constraints, what to avoid — is on you to write.
